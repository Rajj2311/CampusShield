## 📱 About

**Chowkidar** is a cross-platform mobile application built with Flutter & Firebase, designed to digitalize and streamline the daily management of college hostels in India.

Built for **IILM University, Greater Noida**.

The app connects four independent user roles — Warden, Student, Guard, and Worker — through a single shared, real-time Firestore backend, with no dedicated application server to maintain.

---

## 👥 User Roles

| Role | Access |
|------|--------|
| 🧑‍💼 **Warden / Admin** | Attendance, leave approval, complaints, notices, students, device & gate approvals |
| 🎓 **Student** | Attendance, leave request, QR gate pass, complaints, mess menu |
| 🛡️ **Guard** | QR gate scanner — auto exit/return detection, gate history |
| 🔧 **Worker** | View & resolve assigned complaints (Electrician, Plumber, etc.) |

## ✨ Features

### 🎓 Student
- ✅ Mark daily attendance — restricted to an 8:00–9:00 PM window, GPS-geofenced within 200m of campus, with mock-location detection and mandatory live photo proof
- ✅ Apply for leave & receive an auto-generated QR Gate Pass on approval
- ✅ Submit complaints, auto-routed by category to the correct worker and warden
- ✅ Verify complaint resolution (Fixed / Not Fixed) before it's closed
- ✅ View mess menu, notices, profile
- ✅ In-app notification centre
- ✅ Device-bound login — one account, one phone, with a warden-approved exception flow for legitimate device changes
- ✅ Self-service password reset (sent only to the email already on file)

### 🧑‍💼 Warden
- ✅ Hostel-block-scoped attendance management, with an automatic daily reset (mirrored client-side and via a scheduled Cloud Function)
- ✅ Complete attendance history (date-wise, expandable)
- ✅ Leave request approval/rejection — approval auto-generates the QR gate-pass token
- ✅ Complaint management dashboard (before/after photos, once Storage is enabled)
- ✅ Post notices to all students in their block
- ✅ Edit the weekly mess menu
- ✅ Bulk-import students from an Excel spreadsheet (roll no., name, room, block)
- ✅ Approve or reject student device-change requests
- ✅ Approve late-return gate escalations raised by guards
- ✅ System-wide activity log

### 🛡️ Guard
- ✅ Single QR scanner that automatically infers Exit vs. Return from the leave request's current state — no manual selection needed
- ✅ Late-return leaves are escalated to the warden rather than silently completed
- ✅ Students-currently-out live list
- ✅ Full gate activity log

### 🔧 Worker (Electrician / Plumber / Carpenter / Housekeeping / WiFi-Network / Other)
- ✅ View complaints assigned specifically to them, filterable by status
- ✅ Accept complaint → mark In Progress
- ✅ Mark Resolved → awaits student verification before closing
- ✅ Not scoped to a single hostel block — services the whole campus

## 🚀 Getting Started

### Prerequisites
- Flutter SDK (Dart ^3.11.5)
- Firebase project
- Android Studio / VS Code

### Setup

```bash
# Clone the repo
git clone https://github.com/yourusername/chowkidar.git
cd chowkidar

# Install dependencies
flutter pub get

# Run the app
flutter run
```

### Firebase Setup
1. Create a Firebase project at console.firebase.google.com
2. Enable Authentication (Email/Password)
3. Enable Firestore Database
4. Enable Storage (**Blaze plan required** — currently pending; complaint photo upload is disabled until this is active)
5. Enable Remote Config and publish the three role-registration parameters (see below)
6. Run `flutterfire configure` to generate `firebase_options.dart`
7. Deploy the scheduled Cloud Function: `firebase deploy --only functions`

## 🔐 Role Registration Codes

Unlike earlier versions of this project, registration codes for Warden, Guard, and Worker accounts are **not** hard-coded in `lib/constants.dart`. They are served through **Firebase Remote Config** (via `remote_config_helper.dart`), with hardcoded fallback defaults used only if Remote Config is unreachable.

This means the codes can be rotated remotely (e.g. after a leak) without shipping an app update.

> ⚠️ Set your own values in the Firebase Console → Remote Config before going live, and rotate the fallback defaults in `remote_config_helper.dart` too.

## 📊 Firestore Collections

| Collection | Purpose |
|-----------|---------|
| `students` | Student records — roll, name, room, block, boundDeviceId, todayStatus |
| `wardens` | Warden accounts, scoped by hostelBlock |
| `guards` | Guard accounts |
| `workers` | Worker accounts, scoped by category |
| `attendanceRecords` | One document per attendance mark (date, GPS, distance, photo) |
| `leaveRequests` | Leave applications — status + independent gateStatus lifecycle |
| `complaints` | Complaint lifecycle — auto-assigned worker & warden, verification flag |
| `notices` | Warden-authored, block-scoped announcements |
| `messMenuDays` | Weekly mess menu, 7 documents (Sun–Sat) |
| `notifications/{uid}/items` | Per-user in-app notification inbox |
| `gateHistory` | Append-only guard scan log |
| `activity` | Global activity feed for warden oversight |
| `deviceChangeRequests` | Pending device-rebind approvals |
| `settings/attendanceReset` | Singleton tracking the last daily reset date |

## 🔑 Key Security Mechanisms

- **GPS Geofencing + Mock-Location Detection** — attendance rejects any position flagged `isMocked` by the platform location provider, before distance is even checked.
- **Time-Windowed Attendance** — marking is only possible 8:00–9:00 PM daily.
- **Device Binding** — each student account is tied to one device fingerprint; a mismatch triggers a warden-approved device-change request instead of an outright block.
- **Dynamic Dual-Purpose QR Token** — a single gate-pass QR automatically resolves to Exit or Return based on the leave request's current `gateStatus`, with late returns escalated to the warden.
- **Role-Scoped Firestore Security Rules** — students, guards, workers, and wardens can only read/write data appropriate to their role and (for wardens) their own hostel block.

## ⚠️ Known Limitations

- Complaint before/after photo upload is coded but currently disabled pending Firebase Storage activation on the Blaze plan.
- The 200m geofence reference coordinate is hard-coded per campus, not configurable per hostel block.
- Mock-location detection relies on the platform's `isMocked`/`isFromMockProvider` flag, which is a strong but not absolute guarantee against a rooted device with driver-level GPS spoofing.
- Automated test coverage is currently minimal; validation has primarily been manual and field-based.
